# Most recent epoch posted to L1

The live OL report and the time-machine report show the **most recent observed OL epoch posted to L1**. This is the highest decoded `CheckpointPayload.new_tip.epoch` in confirmed, retained history attributable to the watched OL wallet. It is neither a count of settlements nor the Bitcoin height. EE DA postings do not supply this OL checkpoint field.

Each observation includes the reveal transaction, its Bitcoin block/hash/time, confirmations at the snapshot's block, the consumed L1 height, and the terminal OL slot/block ID. The consumed L1 height is a field inside the checkpoint and differs from the Bitcoin block containing its reveal. Pending reveals never advance the reported epoch. The replay uses only transactions visible at the selected block, including when the EE wallet is selected: the displayed context comes from the OL snapshot at that same block.

## Release and decoding evidence

The decoder is pinned independently of the existing runway-model assumption to [`alpenlabs/alpen` v0.3.2, commit `60dae8ee2ed9ec9c75b9e52a7382b7c52d7835b6`](https://github.com/alpenlabs/alpen/tree/60dae8ee2ed9ec9c75b9e52a7382b7c52d7835b6). Its [`Cargo.toml`](https://github.com/alpenlabs/alpen/blob/v0.3.2/Cargo.toml) pins both ASM and strata-common to `v0.3.0-rc.2`.

- Alpen's [`checkpoint_extract.rs`](https://github.com/alpenlabs/alpen/blob/v0.3.2/crates/csm-worker/src/checkpoint_extract.rs) identifies the tagged reveal and reads `payload.new_tip().epoch`. Alpen additionally verifies sequencer predicates, progression, manifest commitments and proofs before accepting a checkpoint.
- ASM's [`constants.rs`](https://github.com/alpenlabs/asm/blob/v0.3.0-rc.2/crates/subprotocols/checkpoint/txs/src/constants.rs) assigns checkpoint subprotocol ID **1** and transaction type **1**. Its [`parser.rs`](https://github.com/alpenlabs/asm/blob/v0.3.0-rc.2/crates/subprotocols/checkpoint/txs/src/parser.rs) reads the first envelope in the first input's Taproot leaf script.
- Strata-common's [`tag.rs`](https://github.com/alpenlabs/strata-common/blob/v0.3.0-rc.2/crates/l1proto/txfmt/src/tag.rs) locates the SPS-50 tag in output **0**. [`parser.rs`](https://github.com/alpenlabs/strata-common/blob/v0.3.0-rc.2/crates/l1proto/envelope-fmt/src/parser.rs) concatenates data pushes within the envelope.
- [`CodecSsz`](https://github.com/alpenlabs/strata-common/blob/v0.3.0-rc.2/crates/codec-utils/src/ssz_shim.rs) prefixes SSZ bytes with a length using the upstream [big-endian 1/2/4-byte varint](https://github.com/alpenlabs/strata-common/blob/v0.3.0-rc.2/crates/codec/src/varint.rs). The SSZ [`payload.ssz`](https://github.com/alpenlabs/asm/blob/v0.3.0-rc.2/crates/subprotocols/checkpoint/types/ssz/payload.ssz) starts with the tip: little-endian epoch `u32`, consumed L1 height `u32`, OL slot `u64`, then the 32-byte OL block ID. The slot stays a decimal string in JSON to preserve all 64 bits.

The mainnet magic defaults to `STRA` (`53545241`), observed in the existing provenance-stamped mainnet OL fixture. Other deployments can explicitly set `checkpoint_reporting: { "magic_hex": "..." }` in network configuration; they have no inferred default. The release defines configurable magic, not a universal network identifier. The chain checkpoint and watched wallet still establish the monitored network and attribution.

The public Signet profile explicitly sets `ALPN` (`414c504e`). Its October 2 read-only capture supplies `test/fixtures/signet/ol-epoch-v032.json`: epoch **185**, consumed L1 height **324650**, OL slot **1850**, posted in block **324662**. The captured framing is compatible with the decoder; it does not establish the deployed sequencer version. Mainnet's default marker does not decode this Signet fixture.

The stored fixture decodes to epoch **103**, consumed L1 height **969386**, OL slot **1030**, posted in Bitcoin block **969392** by reveal `caddf4da10c387cd0b9b0a8ef551a64a9fc5286c6a5a7979cd46fd12bec13630`. This is a historical test vector, not a hardcoded current epoch.

## Coverage and interpretation

This monitor decodes the posted claim and checks its envelope framing, top-level SSZ offsets, sidecar offsets and size bounds. It does not execute the state diff, decode/validate every OL log, verify the ZK proof, authenticate the sequencer predicate, or query ASM acceptance. Therefore the report deliberately says **observed** and does not call the checkpoint accepted or finalized. A confirmed wallet-funded posting is evidence of publication, not proof of protocol validity. The configured upstream deployment remains unconfirmed unless independently established.

Only reveals linked to commits funded by discovered wallet scripts qualify. Epoch selection uses the epoch number, with deterministic block-height/transaction-ID tie breaking for repeat postings, rather than block timestamps. It shares the existing scan's history retention, gap-scan and finality assumptions. Partial history/discovery and tagged postings that cannot be decoded are visible warnings; a more recent epoch may be missing. No decoded checkpoint means unavailable, not epoch zero. Genuine epoch zero is preserved.

Snapshots store optional `epochContext` alongside existing data, so no database migration is needed. Older snapshots remain readable and report the field as not collected. New collection fills it; existing replay results require `pnpm replay run` (or `refresh`) to compute it before HTML regeneration. `replay report` alone cannot manufacture missing historical evidence. Report/API reads remain offline and never contact a provider.

The merged Signet collector compacts stored witness data. Version 2.3 preserves the first envelope's validated length and at most 68 payload bytes in a versioned, local-only cache before removing the witness. This retains checkpoint offsets and EE metadata, including headers split across reveals, while discarding proof/state-diff payloads. Provider responses cannot supply the cache, and freshly fetched witness data always takes precedence. Old compacted records without these headers stay explicitly undecodable until refreshed; raw offline archives remain unchanged.

Prometheus adds `bridge_wallet_posted_epoch_available`, `bridge_wallet_posted_epoch_coverage_complete`, `bridge_wallet_latest_posted_epoch`, and `bridge_wallet_latest_posted_epoch_block_height` for OL. Consumers should also use the existing snapshot freshness metric. The epoch value is emitted only when an observation exists; coverage is false when history/discovery is partial or any tagged posting cannot be decoded.

## EE DA progress

The EE section separately reports the **most recent observed EE DA update fully posted to L1**. Alpen v0.3.2's [`DaBlob`](https://github.com/alpenlabs/alpen/blob/v0.3.2/crates/alpen-ee/da/types/src/blob.rs) carries `update_seq_no` and the terminal EVM header's block number/timestamp. These are big-endian `u64` fields, preserved as decimal strings in JSON. The EE sequence is independent of the OL epoch; the release's internal batch index is `update_seq_no + 1`, not the same identifier.

The commit's output-zero marker is `ALPN` followed by the big-endian blob version, currently zero. The decoder attributes the commit to the watched EE wallet and follows its consecutive P2TR outputs in output order, matching the upstream [`commit/reveal parser`](https://github.com/alpenlabs/alpen/blob/v0.3.2/crates/alpen-ee/da/types/src/commit_reveal.rs). Each output needs exactly one confirmed, wallet-linked reveal at or before the snapshot's tip. Missing chunks leave that publication pending and never advance the latest complete sequence. Chunks can split the metadata header and confirm across multiple Bitcoin blocks; completion is reported at the last required transaction's block.

The report includes the terminal EVM block, confirmed chunk count, payload bytes, completion block/time/confirmations, and commit/reveal transaction IDs. Sequence zero is valid. Unsupported blob versions, malformed/ambiguous reveal evidence, and incomplete discovery/history remain visible. Header decoding does not validate the state diff, proof, or acceptance by OL. Optional `eeDaContext` preserves old snapshot compatibility. Live collection and offline replay use the same extraction and display logic; replay cannot see future reveal chunks.
