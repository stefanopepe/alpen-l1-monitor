# First release decisions

The human request settles steps 1–2 and explicitly asks for naive runway. This narrows PLAN.md's full alert-system scope, including the brief's prohibition on using a simple division as the final selector runway. We keep PLAN.md and the brief unchanged and label the implemented estimate `naiveRunway` / `bridge_wallet_naive_runway_days`. It is not the selector simulator or an operational funding guarantee.

- **Stack:** Node 24, strict TypeScript ESM, pnpm, Vercel Node functions, pg/Postgres, Zod, audited scure/noble derivation libraries. No frontend framework or ORM. TypeScript 6.0.3 is pinned because the available TypeScript 7 release is not supported by typescript-eslint.
- **D-01…D-05:** dual-chain discovery, persistent watched addresses, `/utxo`-only inventory, exact 546 boundary, tip-consistency retry, explicit lower bounds and safe integer accounting.
- **D-20…D-28:** layout-independent commit recognition, script-path reveal validation, integer fee identities, per-address history cursors, truncation rejection, bounded resumable history, checkpoint-bound providers and provider-atomic failover. Finality uses six blocks; shallow cached transactions are rechecked. This release samples confirmed history only. Mempool activity still participates in discovery and inventory semantics.
- **D-13 adapted for naive runway:** use the plan's 30/7-day median-interval cadence with running-max block times, not count/span. Cost is the observed median complete-settlement spendable drain, taking the larger eligible 7/30-day value. This avoids inventing fee scenarios in the reduced release. `aggregateDays` is clearly a contrast value; spendable is the primary numerator.
- **D-30/D-33:** one stamped database per network, pooled runtime connections, separate read credentials, direct migrations with checksums and a migration lock, expiring database lease plus fencing, successful-slot dedupe, per-wallet commits and independent budgets.
- **Schema reduction:** the full settlement/alert schema is deferred. Bounded raw confirmed transaction/history state is JSONB per wallet; typed snapshot amounts are generated columns with database partition checks. Latest inventory and snapshots are retained, daily inventory samples live 30 days, raw snapshots 14 days, daily extrema/count rollups 730 days, history 90 days and run records 90 days. Additive migrations can later normalise settlement history without changing the pure model or chain interface.
- **D-70:** ship public Blockstream primary and mempool failover for Stage 0 only. Internal-provider authentication is environment-referenced. No invented internal URL, signet descriptors, production build confirmation or Grafana setup.
- **Read contract:** only stored data; missing data emits liveness with timestamp zero and no invented balances. Auth is separate from cron. Manual refresh is POST and requires the write credential.
- **Replay boundary:** `ChainView` supplies discovery/history/UTXO reads; `computeWalletSnapshot` is pure, takes explicit time and contains no I/O. An eventual height-restricted view and archive can reuse these functions. Historical replay itself is not shipped.

The scaffold is prepared for tag-driven deployment; this session does not mark a release deployed merely because it builds locally.
